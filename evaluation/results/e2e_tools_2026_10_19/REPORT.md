# 2026-10-19 独立画像与全工具端到端审计

本轮测试已完成，**产品端到端验收未通过**。当前版本能够保存会话、恢复收藏、限制跨身份访问并执行全部工具；实际用户流程仍存在硬条件更新错误、长期偏好未落实到搜索、多工具结果被丢弃和证据归属错误。下面的通过数字分别对应具体检查层级，不能替代用户任务验收。

测试期间没有修改应用或既有回归测试代码。冻结版本、依赖、逐轮证据与结果见 [VERIFICATION.json](VERIFICATION.json)、[源码核验](evidence/product-source-verification.json) 和 [完整工具矩阵](TOOL_COVERAGE.json)。

## 测试范围与隔离

重新创建了 3 个 `fork_turns=none` 的独立 subagents，分别模拟中文留学生、英文上班族、有轮椅使用者和孩子的家庭。它们只收到产品说明、画像、工具覆盖目标和测试环境说明，没有继承主 agent 的完整历史，也没有预先获得旧修复报告。三组画像串行执行；主 agent 另外使用独立合成登录身份检查协议、并发、记忆隔离和故障恢复。

房源来自冻结的历史缓存。容器使用 `--network none`、只读应用源码、独立数据库；房源生产入口强制 cache-only，应用出站和浏览器外链均被拦截。模型请求经 Unix socket 转发，仅允许既有配置的 `api.deepseek.com`，上限为 320 请求、160 万已报告 tokens。

**OnTheMarket 实际出站为 0，应用房源 HTTP 尝试也为 0。** 浏览器中的房源图片、外链和在线地图资源没有放行。[隔离记录](evidence/network-isolation.json)、[房源快照校验和](evidence/snapshot-manifest.json)

TfL、警方、OSM、天气和网页搜索的 HTTP 响应使用固定合成夹具。实际工具实现、参数校验、调度、计算、条件筛选、数据库和界面保持真实。正向夹具验证不代表线上上游当前可用，也不代表房源今天仍可租。

## 后续修复

1. **先统一条件状态，再修最终回答。** 将 P1 地点、预算、撤销、记忆四组纳入一条结构化状态更新链；然后修复通勤校验抹除其他结果的问题。这样可以对同一组冻结输入复验工具参数、卡片资格和文字答复。
2. **补全证据契约。** 房源、详情、路线、票价、安全和 POI 返回稳定实体标识、实际查询位置、数据时间、缓存状态与执行维度。历史详情曾被说成 “live/current asking rent”（F09）；来源标记要能贯穿详情和最终答复。
3. **区分未查询、失败和查询为空。** 自然追问 fare／Travelcard／线路状态时，有几轮没有调用工具却说没有结果；学校／GP 也没有真正查询。返回已执行、失败和不支持的类别及实际半径，不把未执行描述成空结果。F04、上班族 R5–R7。
4. **尊重本轮工具范围。** 家庭明确说不计算通勤，R7/R10/R14 仍实际计算，部分答复又声称没运行。先按用户当前意图约束自动 fan-out，再准确披露执行情况。R4 的交通总预算问题也被零模型的“月租转周租”快捷路径抢答，应收窄该路由的触发条件。
5. **修复连续使用和可访问性。** 刷新后精确房源焦点退化，已有 viewed URL 没被用于消歧；需要持久化每会话的选中房源并恢复。手机侧栏关闭时仍能 Tab 到屏外按钮，打开后 Escape 无效且焦点进入遮罩背景；应同步隐藏／焦点行为、提供退出和焦点返回。缺失标签和动态播报另作真实辅助技术验证。
6. **修复提示与澄清控件。** 429 被说成连接错误；合成模型 503 在 1.94 秒内被说成 time budget。保留错误类别和 Retry-After。`ask_user` 的 A/B/C 只有纯文本，若提供可点击选项，应增加结构化选项并在选择后才提交条件。中文回答还混入内部英文资格原因。

“可以帮忙联系中介”的措辞有前后不一致，但本轮没有请求或执行对外联系，保留为能力表述待核验项，未计作已复现的发送失败。

## 长期使用与故障恢复

进行了 4 次真实容器停止／启动：前两次用于画像连续使用，后两次用于强制登录及撤销状态复验。原数据库、模型配置和签名密钥在重启间保留。

- 学生重启恢复 8/8：两会话、聊天、收藏、收藏价格与原预算、刷新和零新增聊天。[恢复结果](student/recovery-results-restart-1.json)
- 上班族重启后，聊天全文及哈希、筛选和收藏与基线一致。[恢复基线](professional/recovery-before-restart.json)、[恢复结果](professional/recovery-after-restart.json)
- 家庭重启后恢复全部 14 条用户消息，精确 URL 详情仍能查询；错误的 Camden／四卧表单状态也被保存。[恢复状态](family/ui-after-restart.json)
- 天气正常 → 合成 503 → 正常：真实触发三次失败尝试，没有编造旧天气，下一轮恢复成功。[切换记录](evidence/fixture-mode-events.jsonl)
- 模型合成 503 → 正常：请求有界结束，随后同会话恢复真实天气工具；故障分类仍不准确。[模型故障断言](evidence/model-outage-checks.json)
- 退出、删除账号后，原始 Cookie 的读写访问在重启后仍被拒绝；其他身份数据保留。[跨身份汇总](evidence/api-total-summary.json)

这些结果证明了本地重复会话和实际重启下的技术恢复。错误语义同样会被持久化，因此当前的长期体验仍未通过。没有执行真实数周的持续运行、所有 TTL 到期或所有浏览器／辅助设备组合。

## 证据与复验说明
