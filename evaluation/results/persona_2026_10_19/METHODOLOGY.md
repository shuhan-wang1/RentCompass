# 三类用户独立测试的方法与边界

本轮采用三位 `fork_turns="none"` 的独立 subagents，分别模拟中文留学生、英文上班族、有无障碍需求的家庭。测试员只得到画像、产品入口、公开测试工具和环境限制，不继承主对话，不读取产品源码、历史修复说明或其他测试员报告。各自独立制定任务。实际聊天按画像依次执行；下一位可提前准备脚本和浏览公开界面。测试期间不修改产品，不把前一位发现提供给后面的测试员。

每位至少执行 24 轮实际对话、4 组模拟使用会话、3 个对话，其中一个连续 12 轮；包含桌面/手机、浏览器关闭重开、一次实际服务重启和身份隔离检查。具体完成量以各自会话矩阵及原始记录为准。核心流程通过真实浏览器输入框执行，公开 HTTP 响应仅用于辅助核对。

## 被测版本与环境

冻结的是用户当前工作区，包括先前已完成但尚未提交的修复。共复制 1,651 个非忽略文件，排除 `.env`、生产运行目录和 Python 缓存。源文件 SHA-256 清单的摘要为 `03dfa0aa7078219e373ffb15d33a3102012c25285e70c7a85a30faa31b8fde55`；最终再次检查文件未变。该摘要是测试清单身份，不是 Git commit。

| 项目 | 本轮设置 | 对结论的影响 |
| --- | --- | --- |
| 入口 | 本机 `127.0.0.1:15004`，Docker Unix socket 转发 | 不重新开放正式网站；不测试生产 HTTPS、反向代理和公网登录策略 |
| 应用依赖 | 现有 `uk-rent-agent:latest` 镜像，挂载冻结工作区 | 使用项目实际依赖与当前实现 |
| Agent 与发布配置 | `fc_loop`，本地启动记录 `strict=false`；工作区版本标识，关闭发布元数据/LLM readiness 强制要求 | 不是生产环境变量等价性或发布门禁测试；health 仅用于本地停启就绪判断 |
| 对话模型 | 现有 DeepSeek 配置，真实 API 请求；请求模型 `deepseek-v4-flash` | 不使用预编写回答；输出仍存在模型随机性 |
| 房源 | 已有公开房源缓存的独立副本：33 个区域、883 条区域快照记录 | 不是实时市场，也不保证记录跨区域去重；原始抓取日期见 snapshot.json |
| 房源读取 | 测试适配层强制 cache-only，并设置 stale/possibly_outdated 元数据 | 保留实际筛选、排序、对话、详情逻辑；无法用本轮验证在线抓取、限速或当前可租性 |
| 详情 | 使用已有缓存，关闭搜索后的在线详情补全 | 不因大量详情请求触发来源站风控 |
| 网络 | 应用容器 `--network none`；进程额外拒绝外部 DNS/连接 | 即使工具尝试访问来源站，也不能建立外部连接 |
| 模型例外 | Unix socket 转发器固定请求 `api.deepseek.com`，总调用上限 500 | 应用仅通过该通道获得真实模型；统计包含后台记忆与预检调用 |
| 浏览器 | Chromium，桌面 1440×960 / 手机 390×844；只允许测试站 origin | 房源图片、外部字体、地图等都在发出前拦截；空白图片及宿主中文字体缺失不计为产品缺陷 |
| 地图/通勤/治安/POI/天气/网页 | 只有已复制的公开数据缓存可用；其他请求立即失败 | 可以检验无数据时的解释与恢复；不能检验实时路线或事实准确性 |
| 向量模型 | 仅允许已有离线模型缓存；关闭预热和 eager init | 排序可能走降级路径，不能用本轮推导生产语义检索性能 |
| 状态 | 新建独立 auth/conversation/checkpoint/memory/outbox 数据库；启用 checkpoint 与后台记忆任务 | 不复制、修改或删除正式用户数据；可以验证真实落库和服务重启恢复 |
| 本地身份设置 | 允许访客及虚构注册账号，HTTP 下关闭 secure-cookie | 检查基本身份隔离；不构成完整认证、安全或渗透审计 |

缓存新鲜度时间只为读取固定快照进行归一化，返回的房源元数据明确标记为过期；因此快照不会被测试适配层宣称为当前在线可租数据。测试员知道这些限制，不会把低预算无房、外部数据不可用等环境事实直接记为产品缺陷。

## 证据和判断规则

每个问题保留输入、响应、对话/turn 标识、截图或 DOM、期望与实际、复现路径及局限。独立报告分别标记产品缺陷、设计/体验问题、环境限制、单次未定位失败和未验证推测。主报告再依据证据合并同类问题；原报告不改写结论，仅调整持久副本的证据链接。

“HTTP 200”“助手说已保存”“数据库中存在记录”“重开后能读出正确最新需求”是不同的验证项。后台任务与前台对话的调用分开统计。基础设施预检不计入三位测试员的实际对话轮数。

时间、延迟和模型用量只描述这一轮隔离环境；外部数据服务的快速失败会影响延迟，不能当成生产 SLO、真实市场覆盖率、长期故障率或统计可靠的模型准确率。

## 长期使用的边界

本轮是同一天的加速模拟，实际验证连续多轮、跨对话改变需求、关闭后重开和真实进程重启。没有经过真实数周，也没有自然等待登录过期、缓存过期、数据规模增长、每日提醒、长期 outbox 重试或模型版本变化。因此能够判断恢复和状态一致性的样本表现，不能证明数周持续运营稳定性。

所有账号和需求均为虚构；不联系房东，不注册外部服务，不支付，不打开 OnTheMarket 链接，不绕过风控。本轮来源站网络请求为零的判断来自网络边界与浏览器拦截，不能推广为正式部署已经具备跨进程抓取限流或未来不会触发风控。

## 用户明确授权后的 API 补测

后续补测由主协调者执行，没有增加测试subagent或改写前三位的独立结论。新建空测试库、两个账号A/B及两个访客G/H，随后通过公开API新建C复现删除账号后的会话问题。只访问新建的合成数据；不使用原三位测试员的Cookie、账号消息或正式数据。

仍挂载相同冻结源码，但不启用模型、checkpoint和后台任务；应用完全断网，无模型转发器、外部服务或对外端口。通过Unix socket访问真实ASGI/Flask HTTP入口，先允许访客，再开启强制登录；两阶段均关闭legacy客户端身份。已完成消息和回放记录由现有ConversationStore写入，仅作为资源夹具，未替换认证/所有权逻辑；C的复现全部通过公开API。

259次HTTP请求产生253项断言，244通过、9项归于两个会话撤销主题。原来79轮聊天、380次模型请求等统计保持独立；此次模型和OnTheMarket请求均0。补测额外真实重启2次，结束后删除临时Cookie、密码状态和本地签名密钥。完整证据与限制见 [API补测报告](cross_identity/REPORT.md)。
