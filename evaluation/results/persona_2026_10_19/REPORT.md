# RentCompass 三类用户独立测试汇总

> 本文保留修复前的测试基线。后续修复、代理复核及当前验收结果见 [修复与回归报告](FIX_REPORT.md)。

**综合结论：历史、收藏和登录恢复已有通过样本，所测跨身份资源隔离也通过；补测发现删除账号后旧登录会话仍有效，需优先修复。持续多轮筛选中的条件、资格判断和界面状态也不够可靠。** 三位独立测试员均认为，目前适合作为需要用户核对的找房讨论与资料整理工具，尚不足以独立承担长期选房决策台账。

最明显的共性是：助手能够复述用户需求，却在下一次实际筛选或界面更新时丢失、反转或覆盖这些需求。长期使用的改进重点应放在约束与状态契约、证据验证和结果呈现上。

用户后续明确授权跨身份API检查后，已用全新合成身份补做259次HTTP请求、253项断言：244项通过，9项未达预期，集中于账号删除及普通退出的会话撤销。未发现所测路径跨账号读取/修改其他身份数据。具体修改位置、顺序和验收标准见 [综合修改意见](RECOMMENDATIONS.md)；完整补测见 [跨身份API报告](cross_identity/REPORT.md)。

本轮完成测试、报告与只读代码核对，未新增产品代码修改，也未操作正式服务或正式用户数据库。先前工作区修复保持原样。

### 网络与运行证据

- **本轮实际 OnTheMarket 网络请求为0**：应用容器 `--network none`，只通过Unix socket通道访问固定模型API；房源强制只读历史快照；浏览器在外部房源图片、字体、地图等请求发出前拦截。
- 采用33个区域、883条区域房源快照记录，不保证跨区域去重，也不代表当前可租市场。返回元数据标记过期/待核实。真实DeepSeek模型通过应用运行，未使用预编写回答。
- 1,651个冻结源文件最终核对未变。三次重启前后的会话、消息、收藏、turn与快照计数全部一致；界面恢复另由各测试员独立验证。
- 测试结束时无进行中对话或积压后台任务。临时容器、模型转发器和本机代理均已关闭，临时模型密钥配置已删除；正式容器未被操作。
- 服务端聊天耗时中位5.03秒、经验P95为17.91秒、最长27.82秒。这是外部数据服务被隔离的本次观测，不能作为线上SLO。
- 累计380次模型API请求、2,080,114 tokens，包含后台处理及预检，全部返回200；不等于380轮聊天，未估算费用。

证据：[运行统计](operational_evidence.json)、[网络边界](network_boundary.json)、[三次重启](restarts.json)、[清理记录](cleanup.json)。完整配置差异与限制见 [METHODOLOGY.md](METHODOLOGY.md)。

上述79轮、380次模型调用和3次重启属于原用户模拟。API补测另用新库、无模型、无对外端口，测试两种登录配置并额外实际重启2次；OnTheMarket请求仍为0。其统计与清理见 [补测统计](cross_identity/summary.json) 和 [补测清理](cross_identity/cleanup.json)，不混入原轮次。

## 跨身份 API 补测结论

四个初始身份（账号A/B、访客G/H）的12个非所有者方向，消息、turn列表、版本信息、改名、删除、fork、edit_turn和清理历史共96项全部被404拒绝；合法所有者对照通过。伪造user_id、分支读取、同URL收藏隔离、请求ID回放隔离也通过。强制登录下访客与篡改Cookie被拒绝。

**新发现 SEC-01 / P1：** 删除账号返回forgotten=true、原密码登录已401、账号行已删除后，原先保留的该账号合法Cookie仍被判为已登录，并能POST创建会话得到201。两个独立测试账号复现，其中一个完全通过公开API创建；服务重启后仍可访问删除后新建的数据。原消息确实删除，没有观察到其他账号资料泄漏。这是服务端身份/会话失效校验缺口。

**SEC-02 / P2设计项：** 普通退出后当前客户端已401，但同次登录的Cookie副本仍能访问自身列表。该测试采用“退出撤销当前登录会话副本”的安全目标；不把它描述为凭空伪造身份。

建议先集中校验账号仍有效及会话未撤销，删号撤销全部会话；再加入可撤销session_id完成普通退出的撤销语义。9个失败断言归于这两项，不是9个独立漏洞。

## 优先修复的行为

三份报告共记录32条原始观察，API补测新增2项：合计34条，包括24条产品缺陷观察、9条设计问题、1条单次未定位失败，其中包含重复症状。以下归为14个修复主题，**不是34个独立漏洞，也不是已确认14种独立根因**。原始分类和严重性完整保存在 [merged_findings.json](merged_findings.json)。

## 长期使用的判断

| 维度 | 本轮证据 | 结论边界 |
| --- | --- | --- |
| 历史和收藏持久化 | 三位均验证浏览器重开及真实进程重启后恢复；账号登录恢复也通过 | 支持所测恢复路径，不证明中途崩溃、自然过期或数周规模增长 |
| 最新偏好召回 | 留学生重试后新对话回忆最新£1000 studio；上班族重启后新对话回忆£1600/Watford/整租 | 家庭未执行确认后的长期记忆写入，只验证交接文字与历史恢复；不把它算作长期记忆通过 |
| 条件实际执行 | 三位均有房型、卧室、预算、日期或列表状态不一致 | **目前长期依赖的主要障碍**；记得需求与正确执行必须分别验证 |
| 事实与未知 | 多次正确区分未知通勤、账单、入住、宠物及无障碍；也能生成核实清单 | 资格宣称、来源解释和链接仍有反例，不能全面信任“已核实” |
| 身份隔离 | 原画像UI检查通过；补测四身份96项非所有者读写全部404，伪造ID和篡改Cookie也被拒绝 | 仅覆盖列出的路径，不构成完整安全审计 |
| 身份生命周期 | 删除账号的旧会话在两个账号及实际重启后仍可用 | 必须修复；正常登录恢复通过不代表失效/撤销正确 |
| 主动持续服务 | 家庭与其他画像询问时，助手没有声称已启用每日/每周提醒 | 未真实等待或测试调度，不把询问能力当作功能验证 |

建议下一轮先修会话撤销，并把旧Cookie的删号复现及上述自然输入变成行为回归；接着修约束更新、资格与实体一致性、界面快照同步及手机入口；随后完善记忆多任务、降级回答、收藏元数据和语言连续性。具体拆分见 [修改意见与验收顺序](RECOMMENDATIONS.md)。修复后应继续在禁止OnTheMarket访问的条件下复测这些流程。

## 尚未覆盖

原画像是同一天约13分钟/画像的加速多会话模拟，不是真实数周使用；API补测另做明确的权限和会话生命周期检查。实时可租、真实交通/学校/治安/周边、自然缓存与登录过期、自动通知、长期重试、并发负载、真实移动OS/软键盘/屏幕阅读器、完整安全边界未被证明。外部图片空白、CJK字体缺失和实时提供方不可用已作为环境限制排除。测试配置也不等价于生产发布配置，详见方法文档。

家庭画像最初的一项跨身份消息读取被自动审批拒绝，当时仅完成UI检查；原独立报告保留该历史事实。用户后续明确授权后，已使用全新合成身份完成同类API及扩展检查，当前结果见补测报告；未读取原先被拒绝的旧会话，也不把审批事件当产品失败。
