2. **数据不足**：n 不够就跑能跑的，报告里写明实际 n，不要为凑数放宽筛选条件。
3. **外部工具挂了**：记录失败率，用缓存/快照继续；在报告里标注该结果受外部可用性影响。

6. **任何一步失败**：记录后继续下一个实验，不要因为 A 挂了就放弃 B 和 C。

## 5. 证据纪律

- 每个数字六项齐全：`baseline` / `数据集·split` / `n` / `seed·运行次数` / `live 还是 mock` / `来源文件路径`。缺一项标 `INCOMPLETE`。
- **机制验证 ≠ 质量结论**（故障注入验的是异常处理，不是答案质量）。

- **bootstrap 95% CI 跨 0 → 写「未观察到显著差异」**，不许写成「提升」。

## 实验 B：可信推荐的独立模型盲审

现有 152/204 是启发式文本标记评分，不是答案正确率。

- 从**未参与调参**的请求中按 7 类**分层抽 50 例**，至少覆盖多轮重排、通勤约束、多约束冲突。抽样种子写进报告
- 固定工具证据快照；**盲化**：不告知配置，呈现顺序随机打乱（种子落盘）
- 评审员 `deepseek-v4-flash` 标注四项，每项给判定 + 一句依据：
  ① 硬约束是否满足 ② 数值/地点主张是否有证据支持 ③ 与证据矛盾的主张数 ④ 推荐是否可直接执行
- **两轮独立评审**（不同 seed + 不同顺序），算 Cohen's κ。
  ⚠️ **这是同一模型的自一致性（self-consistency），不是评审者间信度。报告必须这样措辞。**
- 若时间允许，用另一家模型跑第三轮，报告跨模型一致率（比同模型两轮有意义得多）
- **人工校准集**：从 50 例中划 15 例，生成 `human_calibration_sheet.md`（每例：请求 / 工具证据 / 系统回答 / 四个判定项留空）供人工标注。
  **本 goal 不等待人工标注。**模型盲审结论一律标注「待人工校准」，直接进入下一实验
- 产出：`evaluation/results/llm_blind_review/`（`round1.json`、`round2.json`、`agreement.json`、`human_calibration_sheet.md`）

## 最终报告必须包含

1. **头部**：`git rev-parse HEAD`、`git status --short`、分支、开始/结束时间、总请求数、失败数
2. **三节实验**：设计 / n / 运行次数 / live 或 mock / 指标表（含 CI）/ 限制 / **结论（支持 · 不支持 · 证据不足）**
3. **fact-ledger 补丁**：可直接粘贴的表格行，每行六项齐全，并给出建议状态标记（`[SAFE]` / `[SAFE-WITH-SCOPE]` / `[CAUTION]` / `[BANNED-FOR-CV]`）
4. **CV 措辞建议**：每个可用数字给一句「可以这样写」，并列出**不可以**的写法。遵守下表：

| 不可以写 | 只能写 |
|---|---|
| 人工评审 / 双人盲审 / human evaluation | 独立模型盲审 / 第三方模型评审 |
| 评审者间信度 κ | 同模型两轮自一致性 κ（或跨模型一致率） |
| 答案准确率 / 正确率 | 证据支撑率 / grounding fidelity |
| 显著提升 | 需 bootstrap CI 支撑才可用「显著」，否则写具体数值与运行次数 |
| 端到端提速 X% | 写清阶段（检索阶段 vs 端到端），两者不可混用或相加 |
| 线上 SLA / 生产指标 | 自建基准上的离线/live 实验结果 |

5. **未完成清单**：没跑成的、样本不足的、被环境阻断的，逐条列原因
6. **次日待办**：需要人工做的事（人工校准集标注等）
